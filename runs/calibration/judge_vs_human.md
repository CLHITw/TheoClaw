# LLM 裁判 vs 線上用戶評分（第一輪，2026-10-20；同日重新分析）

線上用戶收到的回答，由兩個 LLM 裁判盲評（DeepSeek-V4.1-Flash 經 API；Claude 以會話內子代理），各評 2 遍，與提問者本人的 0–10 評分對比。雙方用同一張量表（config/human_rubric_10.yaml，**7 分以上 = 可用**），裁判看得到題目、完整工具輸出與回答，看不到人工分數、評分人與模型名。

## 更正說明

第一版分析把用戶 ≥6 分當『可接受』、裁判 ≥7 分當『可用』，兩邊門檻不一致。這使所有分歧看起來都是『裁判比人嚴』，並把用戶給 6 分（按量表即不可用）、兩個裁判都給 9 分的兩條回答排除在『危險錯誤』之外。本版改用量表本身的同一條規則（雙方都是 ≥7 = 可用），bootstrap 改為先抽評分人、再抽其回答（與方法描述一致），並計算裁判作為『壞答案偵測器』的召回率。舊口徑只保留為對照列。

## 一、數據

- 有分數的（評分人，回答）配對：12 個（另有 1 個『跳過』）；評分人 6 位（R1–R6），每人只評自己問的題（自評滿意度，不是盲評專家判斷）；牧者 2、會眾 10。
- 用戶分數：{6: 2, 7: 2, 8: 5, 9: 1, 10: 2}；按量表『不可用』（<7）的有 2 條。
- 局限：n 很小；每條回答只有一位評分人；多輪對話的後續輪，裁判看不到上文。

## 二、一致度（n=12，95% 區間：先抽評分人、再抽其回答，4000 次）

| 指標 | DeepSeek（2 遍平均） | Claude（2 遍平均） |
|---|---|---|
| Spearman ρ | 0.15 [-0.54, 0.83] | 0.15 [-0.56, 0.83] |
| MAE（0–10） | 1.38 | 1.46 |
| 平均差（裁判 − 用戶） | +0.21 | -0.12 |
| 『可用』判斷一致率（雙方 ≥7） | 58% [22%, 91%] | 58% [22%, 91%] |
| Cohen's κ / Gwet's AC1（同上） | -0.25 / 0.38 | -0.25 / 0.38 |
| 對照：舊口徑一致率（用戶 ≥6 vs 裁判 ≥7） | 75% | 75% |
| 自一致（兩遍 MAE / Spearman） | 0.42 / 0.80 | 0.42 / 0.93 |
| 長度偏差（回答字數 × 裁判−用戶 的相關） | 0.28 | 0.37 |

|---|---|---|---|---|
| DeepSeek | 7 | 3 | 2 | 0 |

## 三、裁判當『壞答案偵測器』

- DeepSeek：用戶判不可用的 2 條，裁判抓到 0 條；裁判標為不可用的 3 條裡，用戶也判不可用的 0 條。
- Claude：用戶判不可用的 2 條，裁判抓到 0 條；裁判標為不可用的 3 條裡，用戶也判不可用的 0 條。

兩條被用戶判不可用（6 分）的回答，兩個裁判四遍都給 9 分；裁判扣分的三條（5–6.5 分），用戶給 7–8 分。分歧兩個方向都有，不是只有『裁判更嚴』。

## 四、結論

- **裁判不能代替用戶評分**：分數相關弱（ρ≈0.15，區間含 0），『可用』判斷只有一半多一致，κ 為負；n=12，每條只有一位評分人。
- **也還不能證明它是可靠的警報器**：用戶判不可用的兩條，裁判都沒抓到（0/2）；它抓的三條，用戶都滿意。兩者量的是不同東西：用戶給的是『對我有沒有幫助』，裁判量的是『引文可否核實、內容是否嚴謹』。
- **能確定的**：裁判自己很穩（兩遍 MAE 約 0.4），適合做**回歸測試**——改 prompt 或模型後對固定題集重跑，察覺 1 分以上的退化；當線上警報之前，要先有用戶判不可用的答案來驗證它的召回率。
- **下一輪需要**：低分答案（目前只有 2 條）、同一答案多人評分、軌跡保存對話上文、問題標籤。
